# quant-research-agent — design

## What this is

A research agent that reviews backtest repositories, and — the actual deliverable — an
eval set that measures whether it catches known bugs, refuses to overstate results, and
(v0.3) reproduces a paper's table. The eval numbers are the product; the agent is the
vehicle. Nothing here claims a productivity gain; only what the evals measure is claimed.

## Standard patterns, not reinvented

| Concern | Choice | Why |
|---|---|---|
| Agent loop | Anthropic SDK tool runner (`client.beta.messages.tool_runner`), four `@beta_tool` functions, `max_iterations` cap, per-task and per-run dollar caps | The loop is the SDK's; what we own is the tool surface, the budget and the transcript. Legible in an interview, no framework. |
| Tool exposure | The same functions served over MCP by `qra.mcp.server` (FastMCP) | Claude Code / Codex can use the tools directly. |
| Sandbox | Subprocess in the repo directory, 60 s wall clock, 2 GB address space, scrubbed env, path jail | Docker is v0.2; the tasks are pure-Python and need no network. |
| Scoring | Rule-based set comparison against a label; no judge in v0.1 | A judge needs a calibration set and an agreement number (v0.3). |
| Reproducibility | Every result file carries model ID, prompt version, git SHA, cost; the README table is regenerated by `qra report` | A number that cannot be traced to a run is not a number. |

## Bug-catch suite

One clean reference backtest (`qra.evals.template.CLEAN`: a two-leg spread sold on a
mean-reversion signal, MTM daily, Line-3 fills, full-calendar Sharpe, beta attribution)
and twelve textual mutations, one per class of the taxonomy in *Dollar-Correct, Time-Wrong*.
Each task is a directory with the mutated `backtest.py` and seeded synthetic data; the label
lives outside the directory. Clean controls are scored too: a false alarm on a clean repo
counts against the reviewer as much as a miss.

Each class is planted three ways (`variants.py`): v0 is the reference expression, v1 and
v2 change the anchor line, the idiom, or the function the bug lives in (e.g. exit-day
lumping in `trade_pnl` vs in the aggregation step; missing legs zeroed by `fillna`, by a
dict `fillna`, or by `pivot_table(fill_value=0)`). 36 seeded repos + 3 controls.

The **regex baseline** was written against v0 and is frozen there. Result: 12/12 on v0,
0/12 on v1, 0/12 on v2, no false alarms — the pattern matcher's generalization is exactly
zero, which is the floor a reviewer that understands the mechanism must beat. A runtime
invariant baseline (opentape checks executed against the repo) is a stronger floor and is
queued for v0.3.

Metrics: per-class recall, precision over all findings, false-alarm rate on controls,
false labels per task, cost and turns per task.

## Overclaim-refusal suite

Ten result cards. `qra.evals.overclaim.expected_flags` is the rule (Sharpe > 3, n < 30,
missing basis, CI including zero, sub-period window, exit-day marking); labels are
generated from it, so they are exact. The agent receives the same rules in prose and must
apply them through one structured tool call. Metric: exact flag-set match, per-flag recall,
over-flags per task, wrongly-flagged clean cases.

## Budget

Per-task cap $2, per-run cap $20 (`--cost-cap`, `--run-cap`). CI runs the zero-spend
smoke on every push; paid evals only on `workflow_dispatch` with a 4-task Sonnet limit.
Full runs are manual, pinned by SHA, and committed under `evals/results/`.
