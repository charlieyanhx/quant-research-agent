# quant-research-agent

[![ci](https://github.com/charlieyanhx/quant-research-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/charlieyanhx/quant-research-agent/actions/workflows/ci.yml)
![python](https://img.shields.io/badge/python-3.11%20%7C%203.12-blue)
![license](https://img.shields.io/badge/license-MIT-green)

A research agent that reviews quant backtests — and the evals that measure whether it
catches known bugs and refuses to overstate results. **The eval numbers are the
deliverable; the agent is the vehicle.**

Three questions, each with a scored task set:

| Question | Suite | Scorer |
|---|---|---|
| Does the agent find the bug a backtest is hiding? | **bug-catch** — 36 backtest repos: each of the twelve classes of [*Dollar-Correct, Time-Wrong*](https://github.com/charlieyanhx/backtest-bug-taxonomy) planted three ways (v0 the reference expression, v1/v2 paraphrases through different code), plus 3 clean controls | precision / recall per class and per expression; false-alarm rate on clean repos |
| Does it refuse to overstate a result? | **overclaim-refusal** — 10 result cards (Sharpe > 3, n < 30, no basis label, CI through zero, cherry-picked window, exit-day marking) | exact match on the house-rule flags applied |
| Can it reproduce a paper's table? | *v0.3* — CORE-Bench protocol on the public paper repos | numeric tolerance |

Design rules: rule-based scorers wherever a rule exists (no judge yet); every result file
carries model ID, prompt version, git SHA and cost; the table below is regenerated by
`qra report`, never edited by hand; two zero-spend baselines give every number a floor — a
**regex** matcher that knows the shape of each bug, and a **runtime-invariant** auditor that
never reads the code: it runs the backtest, rebuilds a clean tape from the repo's own data,
and tests invariants (calendar coverage, net ≤ gross, trade count vs an independent signal
count, per-trade totals vs the reference, the README's neutrality claim vs measured beta);
prompts are versioned and a prompt change that moves a number is a PR with the before/after
table.

Read the two baseline columns against each other. The regex matcher was written against
the v0 expressions and is frozen there: all twelve when the bug is written the way it
expects, **none of the 24 paraphrases** — "matched the shape, not the mechanism". The
runtime auditor never sees the code: on every task whose bug actually changes a number or a
claim it detects *something* (100 %) and names the right class 88 % of the time, at zero
false alarms on clean repos; the class it cannot name it reports as "unclassified
deviation", never as a guess. Four seeded tasks are **dormant** — the mutation is in the
code but changes nothing on that seed's data — and only reading can find those, which is the
agent's job. Those two columns are the floor the agent is measured against; its row appears
once a paid run is committed.

## Run it

```bash
pip install -e ".[dev]"
pytest -q                                     # 103 tests, no API calls
qra generate --variants 3                     # 39 bug-catch repos + 10 overclaim cards (deterministic)
qra run --suite bugcatch  --agent lint        # zero-spend regex baseline
qra run --suite bugcatch  --agent runtime     # zero-spend runtime-invariant baseline (~15 s)
qra run --suite overclaim --agent lint
export ANTHROPIC_API_KEY=...
qra run --suite bugcatch  --agent claude --model claude-opus-5 --cost-cap 2 --run-cap 20 --transcripts
qra run --suite overclaim --agent claude
qra report                                    # rewrite the table above from evals/results/
qra review path/to/any/backtest_repo          # the agent on your own code
```

## What is where

```
src/qra/
  agent/orchestrator.py   tool-runner loop; turn cap; $ cap; transcript; AgentResult
  agent/tools.py          list / read / run_python (60 s, 2 GB, path-jailed) / submit_findings
  agent/prompts.py        versioned system prompts (PROMPT_VERSION stamped into results)
  evals/template.py       the clean backtest + the twelve reference mutations
  evals/variants.py       two paraphrases per class (different anchor, idiom, or function)
  evals/generate.py       seeded repos + labels incl. effect: numbers / claim / none (labels never inside a repo)
  evals/overclaim.py      result cards + the rule that labels them
  evals/baseline.py       twelve-pattern regex baseline, frozen at the v0 expressions
  evals/runtime.py        runtime-invariant baseline: runs the backtest, rebuilds a clean tape, tests invariants
  evals/scorers.py        set-comparison scorers and aggregates
  evals/run.py            runner → evals/results/<suite>_<agent>_<model>_<sha>.json
  evals/report.py         README table regenerator
  mcp/server.py           the same tools over MCP for Claude Code / Codex
evals/tasks/              committed task set (repos/, labels.yaml, overclaim.yaml)
evals/results/            committed runs
docs/DESIGN.md            choices and what is deliberately not in v0.1
```

## Agent

Anthropic SDK tool runner on `claude-opus-5` with adaptive thinking; four typed tools;
`max_iterations=30`; per-task cost cap $2 and per-run cap $20 enforced from `usage`.
No framework. The MCP server exposes the identical tool functions so the same review can be
driven from Claude Code.

## Roadmap

v0.3 (shipped): the runtime-invariant baseline. Next: a CORE-Bench-style table-reproduction
suite on the two fully reproducible paper repos, and the overclaim judge with a
human-labelled calibration set and an agreement number. Later: Docker sandbox; a Claude Agent SDK baseline on the same tasks.

## Data and privacy

Everything here is synthetic or public: the seeded repos are generated from one template,
the overclaim cards are fictional. Tools that touch proprietary data stay in a gitignored
adapter; no system prompt names a live strategy.
